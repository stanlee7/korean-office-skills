# 곤란한 업무 메일 답장

받은 메일과 **사용자가 정한 결론**을 받아 답장 초안을 씁니다. 스킬은 결론을 정하지 않고, 정해진 결론을 상대가 기분 상하지 않게 전하는 문장만 씁니다.

## 먼저 확인할 것

답장을 쓰기 전에 아래 두 가지가 입력에 있는지 봅니다.

- **결론**: 거절하는지, 미루는지, 일부만 받는지, 사과하는지
- **상대와의 관계**: 고객, 협력사, 사내 윗사람, 동료 중 무엇인지(없으면 고객으로 보고 가장 정중하게 씀)

결론이 없으면 초안을 쓰지 말고 **한 번만** 묻습니다. 예: 「이번 요청은 거절할까요, 일정을 미룰까요, 일부만 받을까요?」 사용자가 「알아서」라고 하면 가장 보수적인 안(확답 없이 내부 확인 후 회신)으로 쓰고 그렇게 썼다고 알립니다.

## 지킬 규칙 (AI가 덧붙인 약속 금지)

1. **사용자가 말하지 않은 약속을 쓰지 않습니다.** 새 날짜, 할인, 보상, 무상 제공, 「다음에는 꼭」, 「최우선으로 처리」, 「재발 방지 대책 마련」 같은 약속은 사용자가 말한 경우에만 씁니다.
2. **날짜와 숫자는 사용자 입력 그대로.** 미룬 일정, 금액, 수량을 새로 만들지 않습니다. 필요한데 없으면 `[날짜]`, `[금액]`처럼 빈칸으로 둡니다.
3. **책임 인정 범위는 사용자 결론까지만.** 실수 사과 메일에서도 사용자가 인정한 범위를 넘어 「전적으로 저희 잘못」처럼 넓히지 않습니다.
4. **거절은 첫 문단 안에.** 돌려 말하다 결론이 끝에 묻히지 않게, 감사나 공감 한 문장 뒤 바로 결론을 씁니다.
5. **이유는 하나, 짧게.** 사용자가 준 이유만 씁니다. 이유를 주지 않았으면 「내부 사정으로」처럼 두루뭉술하게 쓰고 지어내지 않습니다.
6. **대안은 사용자가 준 것만.** 대안을 주지 않았으면 대안을 넣지 않습니다.
7. **길이는 짧게.** 본문 3~6문장. 인사와 서명 빼고 한 화면 안에 들어오게 씁니다.
8. **존댓말 수준을 맞춥니다.** 고객과 윗사람에게는 「~드립니다」, 「~하겠습니다」, 동료에게는 「~할게요」도 허용합니다.

## 상황별 뼈대

| 상황 | 순서 |
|---|---|
| 거절 | 감사 → 결론(어렵다) → 이유 한 줄 → (사용자가 준 대안) → 마무리 인사 |
| 일정 미루기 | 사과 한 줄 → 바뀐 일정(사용자가 준 날짜, 없으면 `[날짜]`) → 이유 한 줄 → 마무리 |
| 재촉(내가 보낼 때) | 이전 메일 언급 → 필요한 것 하나 → 필요한 날짜(사용자가 준 것) → 정중한 마무리 |
| 범위 밖 요청 | 감사 → 현재 계약 범위 밖임을 한 줄로 → 사용자가 정한 처리(별도 견적, 불가 등) → 마무리 |
| 실수 사과 | 사과 → 무엇이 잘못됐는지 사실만 → 이미 한 조치(사용자가 말한 것만) → 마무리 |

## 출력 형식

```
제목: (답장이면 RE: 원 제목, 새 메일이면 한 줄)

(본문)

※ 확인할 것: 빈칸으로 둔 곳 [날짜] [금액] 등, 사용자가 정해야 할 것
※ 넣지 않은 것: 사용자가 말하지 않아 뺀 약속이나 대안이 있으면 한 줄
```

「확인할 것」, 「넣지 않은 것」은 해당 내용이 있을 때만 씁니다.

## 예시

`예시/입력_거절메일.md`와 `예시/기대출력.md`를 참고합니다(모두 가상 데이터).
